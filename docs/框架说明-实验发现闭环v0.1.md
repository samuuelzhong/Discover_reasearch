# 实验发现闭环框架 v0.1（hydro 域）

> 目标：不是"再做一个 RSI 去解已有假设"，而是**让"观察→假设→实验→分析→异常→新观察"这个环真正闭上，且每一环都有可核对的真值**。
> 域名：CAMELS/CARAVAN 类径流模拟。两条分支都在框架内：① 精度（可验证、可复算）；② 可解释发现（统计判决）。

## 2. 反幻觉：四道机制（不是靠"提示词小心一点"）

| 机制 | 位置 | 作用 |
|---|---|---|
| **只允许已抓取文本** | `core.papers` | 每篇文献入库时存 URL、检索时间、原文 SHA256；模型记忆不进入可信区 |
| **引文逐字校验** | `core.verify_quote` | 引文归一化后在原文里做子串匹配，命中才写 `claims`；否则拒绝 |
| **结构门控** | `hypothesis.check_gate` | 任何一个 citation 无法逐字命中 → 整条假设被拒（已实测：伪造引文被拒） |
| **工具化阅读** | `paper_mcp.py` | 论文以 MCP 工具暴露，`check_claim` 返回带 char offset 的原文段落；`no_support_found` 明确要求"不得引用" |

`paper_mcp` 的判定是**词面支持**（lexical support），不是蕴含判断——这是刻意的保守设计：它不会替你下结论，只负责把证据摆到台面上，并给出"找不到就别说"的硬边界。

## 3. 两条分支各自的"真值"从哪来

**分支 1（精度）**：真值 = 观测径流上的 NSE/KGE。
- 时间切分 60/20/20，标准化与回归系数**只在 train 上拟合**；
- 候选解从不接触 Q（`ctx` 里没有 Q），杜绝标签泄漏；
- 每次评估记录 code_sha + data_sha，可复算。

**分支 2（可解释）**：真值 = 统计检验，不是 LLM 判断。
- 签名：径流比、P–Q 弹性、流量质心日、雪占比、干旱度、flashiness；
- 趋势：Theil-Sen 斜率 + Mann-Kendall p + bootstrap CI；
- regime：按记录中位年切分，Δ弹性 = 后段 − 前段，带 bootstrap CI；
- 判决严格按预注册的 `decision_criteria` 执行（支持/削弱/不确定），事后不许改阈值（门控会检测时间戳倒序）。

**异常通道**：跨流域稳健 z（median/MAD）标记"同类型里的异类"，输出**问题**而不是结论，绕过假设池直接回流到①。
在合成数据上可用已知注入真值校准检测器（`detector_calibration.json` 记录 recall/precision）。

## 4. 数据真实性

| 适配器 | 来源 | 说明 |
|---|---|---|
| `usgs_mini` | USGS NWIS `dv` 00060 日均流量（cfs→mm/d，按 `drain_area_va` 换算）+ NASA POWER 日值（PRECTOTCORR / PRECSNO / T2M / T2M_MAX / T2M_MIN，PET 用 Hargreaves） | 无需登录、可复现；每流域缓存 + 整包 SHA256。**强迫是站点像元/格点，不是流域面平均**，这是已知偏差 |
| `camels_local` | 官方 CAMELS / CARAVAN 文件（csv/txt，列名自动对齐；缺 PET 时用 Hargreaves 补） | 生产路径：放到一个目录，`data --source local --path <dir>` |
| `synthetic` | 文档化的生成器（含**已知** regime shift） | 只用于检测器校准与单元测试，不用于结论 |

选站规则（可复现）：每个州取流量站，按面积降序、限定 80–2500 mi²（避开大型水库调控河流），
记录覆盖率 ≥85%、序列 ≥10 年者保留 6 个。

## 5. 常用命令

```bash
export PYTHONPATH=/e/multiagent
PY=D:/anaconda/python.exe

# 新建 run
$PY -m discovery_loop.cli new --id hydro-r2

# ① 文献（真实 API）
$PY -m discovery_loop.cli papers --run hydro-r2 --n 8 \
  --queries "streamflow simulation catchment climate change" "snowmelt runoff timing shift"
$PY -m discovery_loop.cli prune --run hydro-r2 --keywords streamflow runoff catchment hydrolog snowmelt
$PY -m discovery_loop.cli pdf --run hydro-r2 --paths "文献收集/DiscoveryRSI Recursively Learning to.pdf"

# ①b 论文 → MCP（生成配置，粘贴到 MCP 客户端即可）
$PY -m discovery_loop.cli mcp --run hydro-r2 --paper "文献收集/DiscoveryRSI Recursively Learning to.pdf" --name drsi
# 直接以 MCP 客户端方式提问（演示"可讨论"）
$PY -m discovery_loop.cli ask --paper "文献收集/DiscoveryRSI Recursively Learning to.pdf" --name drsi \
  --tool check_claim --args '{"statement":"credit is assigned through contribution records"}'

# ③ 数据
$PY -m discovery_loop.cli data --run hydro-r2 --source usgs --states ME,NC,CO,WA --per-state 6
# 或官方 CAMELS/CARAVAN
$PY -m discovery_loop.cli data --run hydro-r2 --source local --path /path/to/camels

# ② 假设（预注册，先过门控再跑）
$PY -m discovery_loop.cli hyp --run hydro-r2 --file runs/hydro-r2/hypotheses/drafts.json

# ③ 分支1：进化（RSI）
$PY -m discovery_loop.cli evolve --run hydro-r2 --generations 3 --islands 3 --pop 4
# 分支1 差分消融
$PY -m discovery_loop.cli ablate --run hydro-r2 --specs runs/hydro-r2/specs.json
$PY -m discovery_loop.cli judge --run hydro-r2 --hid H-A1 --design-a "spec0:..." --design-b "spec1:..."

# ④ 分析 + 异常通道
$PY -m discovery_loop.cli analyze --run hydro-r2
$PY -m discovery_loop.cli verdict --run hydro-r2 --file runs/hydro-r2/hypotheses/H-I1.json

# 报告
$PY -m discovery_loop.cli report --run hydro-r2
```

## 6. 已知局限（写进论文的"Limitations"）

1. 强迫为格点值，非流域面平均；大面积/复杂地形流域偏差最大。
2. 样本量（~24 流域）支持趋势与组间比较，不支持区域外推；部分 Δ弹性 CI 跨零。
3. 分支1 的模型族是"线性 + 特征工程"，NSE 属概念性模型水平，不是 SOTA（CAMELS 上 LSTM 常见 0.7+）。
4. 异常通道只产出问题；因果归因需要流域属性、取用水、地下水数据。
5. 假设仍由 Boss（人/我）撰写，系统尚未自主出题——与调研第十一章的结论一致，这是下一阶段的攻关点。
