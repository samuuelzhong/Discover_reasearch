# 方案评审：实验发现闭环架构（手绘图 v1）

> 评审对象：2026-10-27 手绘架构图
> 原图流程：① 实验/观察（文献 Scout：PaperQA2 + Paper2Agent）→ ② 多假设提出/论证/筛选（DiscoveryRSI）→ ③ 设计实验 + RUN（ShinkaEvolve RSI）→ ④ 分析数据 → 回到①；底层 Boss Agent 维护 Shared Summary 并控制 RSI。
> 目标定位：做"实实在在的新发现和实验验证"，区别于当前研究"构建 RSI 解决已有假设"。
> 配套材料：《科研调研-多智能体自主科学发现-2026.md》《精读-DiscoveryRSI-2026-10-27.md》

---

## 一、先说对了什么（这个方案踩中的两个领域级结论）

**1. 方向判断正确：把 RSI 从"解题器"降级为"环节工具"，主线换成实验闭环。**
这正好对齐调研里的核心事实链：

- 代码域 RSI 火爆、湿实验域停滞，根本原因是验证器成本（验证者定律）。**谁先在某个真实实验域把闭环成本降到可承受，谁就占据了目前没人占据的位置**——这比再造一个 agent 拓扑有价值得多。
- 目前"机器提议 → 变成真研究"唯一成活的形态是**带实验闭环的管线**（时域天文异常挖掘、Google 适配体 lab-in-the-loop：三轮命中率 0%→26%→42.1%，$1–3/候选）。你的方案正是这个谱系。
- "区别于构建 RSI 解决已有假设"这个自我定位是准确的：DiscoveryRSI、DGM、OpenRsi 全部在"给定假设/给定 benchmark"上做递归改进；**闭环实验系统里，假设来自环境反馈而不是来自人类出的题**——这是结构差异，不是程度差异。

**2. 组件选型基本正确，没有重复造轮子。**
PaperQA2（文献层）、Paper2Agent（论文工具化）、DiscoveryRSI 的假设结构与盲评、ShinkaEvolve（进化引擎）、Boss Agent + Shared Summary（对应 Anthropic 编排-执行 + Cognition"共享上下文、串行写入"原则）——每个组件都有出处，且互相之间接口清晰。

---

## 二、三个关键问题（按严重程度排序）

### R1（最严重）：ShinkaEvolve 放在"设计实验+RUN"是错位

ShinkaEvolve 是**代码进化引擎**：它需要一个 `evaluate.py`，能在秒~分钟级返回分数，然后进化候选解。它不设计实验、不操作仪器。

三种修法（按推荐顺序）：

- **修法 A（推荐）：实验域选"计算代理 + 少量真实验证"的混合闭环。** ShinkaEvolve 进化的是**实验方案/参数/分析代码**，用模拟器或历史数据当廉价验证器筛掉大部分候选，只有存活者进入真实 RUN。这是 AlphaFold 式"计算筛选 + 实验确认"的 agent 化。
- **修法 B：ShinkaEvolve 只优化"分析管线与实验协议"，不做假设搜索。** 假设空间由第②阶段给，ShinkaEvolve 负责把"怎么跑这个实验"优化到最好。
- **修法 C：如果坚持纯湿实验闭环，把 ShinkaEvolve 换掉。** 参考 Google 适配体工作的模式：agent 只负责提出设计 + 解释失败，执行交给固定实验流程，RSI 作用于"从实验数据诊断失败原因"这一层。

**判据**：问一句"这个域里 evaluate 一次多少钱、多长时间？"——如果答案是 >$10 或 >1 天且不可模拟，ShinkaEvolve 进不去，架构必须改。

### R2：Boss Agent 不能当"价值裁判"，否则退化回橡皮图章

图里 Boss Agent 同时维护 Shared Summary 并"控制 RSI"。风险：MAST 的头号失败模式就是"评审 agent 是橡皮图章"；DiscoveryRSI 实测自我改进后 importance/novelty 双双下滑。

修正：Boss Agent 只做**三件事**——

1. **工作区管理**（Shared Summary，参考阿里 IterResearch：每轮重构轻量工作区，不堆上下文）；
2. **结构门控**（用 DiscoveryRSI 的 H=(c,π,d,a) 检查：判定标准是否预先写明、备择解释是否列出、成本是否可承受——全是机械可判项，即 11.5 节"结构裁判"）;
3. **串行写入**（所有对 Shared Summary 的写入由 Boss 单线程执行，agent 只读——这是 Cognition 复盘后确认唯一稳定的多 agent 模式）。

**不判断**假设好不好、值不值得做——价值的最终裁判是实验数据和真实文献（回溯对答案），不是 LLM。

### R3（致命的逻辑漏洞）：缺"异常通道"，闭环跑得越久越只会解决已有假设

这是最需要指出的：你的目标是"做新发现"，但图里 ④→① 的回路只把"分析结果"喂回"观察"。**没有独立于现有假设的问题发现机制**，这个闭环的稳态就是不断精化第②阶段给出的假设池——恰好退化成你想区别开的"解决已有假设"。

调研已证明：LLM 不会主动提出零假设，per-idea 评分奖励不出真问题；唯一成活的"出题"形态是**环境里有一个自动且便宜的"这不对劲"检测器**。

修正：在第④和①之间加一条**异常通道**——

- 对实验数据建立统计基线（历史 run 的分布）；
- 偏离基线的观测不经过 Boss 的假设池，**直接以"异常报告"形式进入下一轮观察**，附带"哪个变量、偏了多少、可信度"；
- 每隔 N 轮做一次**回溯对答案**（提出的假设 vs 后续文献/后续实验的真值），这是唯一的重要性裁判，同时攒出可发表的评测数据。

**这条通道是你方案相对 Google 适配体工作、相对 Coscientist 的真正增量，也是立项书里"新颖性"声明的落点。**

## 四、补全后的架构（v2 要点）

```
① 观察 ── Scout 层（PaperQA2 + Paper2Agent）──→ ② 假设开发
   ↑                                              │
   │                                    [结构门控：H=(c,π,d,a)]
   │                                              ↓
④ 分析 ◄── RUN（真实实验 + 计算代理）◄───────── ③ 实验设计
   │                                              ↑
   ├── 常规结果 → 回到②（假设精化）        ShinkaEvolve 只优化
   │                                      方案/参数/分析代码
   └── [异常通道] → 异常报告 → ①（新问题来源）

Boss Agent（侧线，不在这条数据流上）：
  Shared Summary 读写串行化 · 结构门控执行 · 成本记账
```

另外三件图里没有但必须有的基础设施：

- **每个 RUN 的数据带哈希归档**（不可复现防护，也是回溯基准的原料）；
- **成本记账**（$/候选、周期天数——这是绘制成本-质量前沿曲线、与 Aptamers 工作对比的硬数据）；
- **分析管线冻结**（④ 的分析代码一旦进入循环就锁定版本，防止 agent 通过改分析代码让自己"发现"变多——reward hacking 在评分即代码的领域必然发生）。

## 五、最小落地路径（4 周）

**第 0 步（决定性）：选域。** 判据（来自验证者定律 + Aptamers 先例）：

| 判据 | 门槛 |
|---|---|
| 单次验证成本 | ≤$10/候选 |
| 循环周期 | ≤2 周 |
| 可计算代理存在 | 有模拟器或历史数据可当廉价预筛 |
| 统计基线存在 | 能定义"这不对劲"（异常通道的前提） |
| 数据结构化 | 输出可自动解析 |

参考域：适配体/生化检测（Google 已验证成本结构）、材料合成（A-Lab 先例）、时域天文异常挖掘（问题发现先例）、细胞表型筛选。

**第 1 周**：ShinkaEvolve 用自带示例跑通 → 把选定域的验证器写成 `evaluate.py`；同域用 OpenEvolve 再跑一轮（引擎可换、裁判不变）。

**第 2 周**：接 Scout 层（PaperQA2 pip 装即用；选 5–10 篇核心论文用 Paper2Agent 思路做 MCP 化）。跑通"文献 → 假设 → 结构门控"。

**第 3 周**：接第一个真实 RUN（哪怕只 5 个候选）。记录：命中率、$/候选、周期、异常通道触发次数。

**第 4 周**：第一轮回溯评估 + 成本-质量前沿曲线初版。产出可直接进开题报告。

**度量协议**（跨轮次，学 Aptamers 的报告方式）：每轮命中率分布、restart 率、异常通道提出的"新问题"数 vs 假设精化数、组合多样性。

## 六、立项书表述建议

- 目标不写"提出有价值的问题"，写：**"以异常检测为代理信号的问题发现 + 假设由实验闭环外部验证"**；
- 核心科学问题写：**"实验数据作为裁判的可靠性边界"**——这是把裁判可靠性主线落到湿实验域，学术上站得住；
- 与已有工作的差异声明：对 Coscientist/A-Lab 是"加了跨环节数据驱动的假设管理"；对 DiscoveryRSI 是"假设来自环境而非人类出题"；对 ShinkaEvolve 类是"验证器从代码换成了真实实验"。
